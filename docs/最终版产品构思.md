# 研擎 NebulaLab · 最终版产品构思
> 三方合流版：宣传册版（智创星云复刻）× LabFlow 战略版 × RBAC/集成平台分析
> 日期：2026-09-27 ｜ 状态：定稿 v1.0

---

## 一、一句话定位

> **课题组的科研操作系统 —— AI 不长在对话框里，而长在任务上。**

以**课题组**为账户单位（不是个人），以 **AI Agent 编排**为执行方式（智创星云骨架），覆盖"学生的第一篇论文"到"导师的组内经营"再到"机构的科研治理"，让科研全流程在同一个系统里闭环运转。

- Slogan：**让科研，自己跑起来。**
- 品牌统一为 **研擎 NebulaLab**（MVP、官网、宣传册、GitHub 资产均已建立；LabFlow 可作为英文产品线名备用）。

## 二、受众（四角色 RBAC + 一个双边入口）

| 角色 | 定位 | 付费 | 在系统里看到什么 |
|---|---|---|---|
| 🎓 本科生/准研究生 | 获客漏斗 + 套磁方 | 免费 | 启航学院、工具百科、引导式复现、成长档案 |
| 🔬 研究生/博士后 | **核心使用者 + 数据源** | 免费 | 文献、复现、投稿、我的任务/报销/档案 |
| 👨‍🏫 导师 / PI | **核心付费方**（组级订阅，走课题经费） | 组 ¥3,000–8,000/年 | 课题组驾驶舱：组盘、负载、套磁、经费审批、管理会议 |
| 🏛️ 院系/科研处 | 机构付费方（私有化部署） | 院级 ¥8–20 万 + 年费 | 全院驾驶舱、经费红线、结题预警、权限矩阵、成果库 |

关键机制：**导师装了 → 学生必须装（收任务）；学生套磁 → 准学生会装；全院在用 → 科研处必须装。** 一个课题组 = 一次部署拿下 5–20 个活跃用户。

## 三、要解决的问题（三层：8 个原始痛点 + 5 个补强痛点）

**A. 学生侧（入口层，原始痛点 1–4、8）**
1. 新手不知道怎么开始科研、不会选工具
2. 文献管不好、读不完、记不住
3. 没有编程经验，复现不了论文结果
4. 找不到创新点、不会选期刊、投稿干等
8. 科研日程（课程/会议/讲座/截止）一团乱

**B. 导师侧（付费层，原始痛点 5–7）**
5. 海量套磁信筛不出最匹配的学生
6. 组内分工凭感觉，能者过载、新人闲置
7. 科研经费管不住（预算/执行/报销/结题）

**C. 补强层（两版都漏了、但决定机构买单的 5 个）**
9. **学术诚信与 AIGC 合规**：AI 参与留痕、披露声明、教练不枪手
10. **实验记录与数据血缘（ELN）**：结论能回溯到哪次 run、哪份数据、哪版代码
11. **审稿响应（rebuttal）**：投稿只是开始，大修小修才是最痛的一公里
12. **知识传承**：毕业不归零，组内经验随人流失 → 自动生成 Handover Packet
13. **经费审计闭环**：不是"管经费"，是"怕审计出问题"——规则引擎预警

## 四、产品架构："1 + 3 + 1"

```
┌─────────────── 角色平面（RBAC 四身份）───────────────┐
│  学生平面「启航流水线」   导师平面「课题组驾驶舱」   机构平面「治理」 │
├──────────────────────────────────────────────┤
│  研擎 Claw（AI 中枢）：八位 AI 员工 · 工作流 · 技能 · IDE     │
├──────────────────────────────────────────────┤
│  连接器层（MCP）：Zotero/Notion/GitHub/Overleaf/豆包API/       │
│  本地模型(GLM/DeepSeek)/校内教务财务 —— 可插拔                 │
└──────────────────────────────────────────────┘
```

**1 个 AI 中枢（承接宣传册版 + 智创星云骨架）**
八位 AI 员工（科研大脑/文献情报/复现工程师/写作教练/投稿顾问/招生匹配官/经费财务/日程管家），自然语言建工作流（借 Zapier），Agent 间分工 handoff + 每次调用带权限边界与审计日志（机构采购第一问）。

**3 个角色平面**

① 学生平面 = **引导式流水线，不是工具箱**（借 LabFlow 版）：
选题定位 → 文献矩阵（自动横向对比）→ 可行性评估 → 零代码复现 → 结果图表 → 成稿排版 → 期刊匹配 → 投稿追踪 → **rebuttal 响应**。每步只问 3 个问题、产出 1 个工件，工件自动进资产层——新手不需要"选工具"，流水线替他选了（解痛点 1–4）。

② 导师平面 = **课题组驾驶舱**（蓝海核心）：
组盘 Board（谁在哪个阶段、卡了多久、红灯预警）、能力×负载矩阵（分工推荐）、招生证据匹配（不是简历匹配，是复现记录/代码仓库的证据匹配）、经费燃烧视图 + 审批流、组会自动化与知识沉淀（解痛点 5–7）。

③ 机构平面 = **治理与资产**：
全院统计、经费红线、结题预警、成果与 IP 登记、AIGC 合规披露、对接学校现有填报系统（只导出、不替代）。

**1 个连接器层（MCP 集成战略，两版都没有）**
- 原则：**红海环节集成别人的（文献→Zotero、写作→Notion/Overleaf），无人区环节自建自己的（驾驶舱/套磁/经费/日程）**
- 交互原则：用户面对研擎的界面，第三方系统是被 Agent 调用的"手"——体验上是"打开研擎就完成了 Zotero 记笔记 + Notion 写作"，但绝不做 iframe 嵌入
- 数据原则：**文档型数据可同步出去，流程数据（任务/组会/审批/实验台账）必须留在研擎库**——这是数据闭环不被稀释的底线
- 模型可插拔：演示版用豆包 API，机构版换本地 GLM/DeepSeek（数据不出校）

## 五、关键裁剪决策（查漏补缺的"减法"）

| 决策 | 理由 |
|---|---|
| **裁掉"研擎 GEO"独立模块** | 概念源自电商、不在 8 个真实痛点内、分散焦点。其有价值的内核（"让成果被 AI 搜索正确引用" + 科研资产沉淀）降级为投稿模块的"学术影响力"子功能 |
| 六模块收敛为三平面 | 对齐 RBAC 四角色，避免"功能巨多的 Student Tool Suite"；叙事从"我们有 6 个产品"变成"一个系统、三种身份" |
| 保留 Claw 中枢与八专家叙事 | 智创星云骨架是最强的故事线与差异化表达，宣传资产已建 |
| 命名统一为研擎 NebulaLab | 全部资产（MVP/官网/宣传册/GitHub）已建立；避免双名内耗 |

## 六、独特竞争力（三层时间轴）

**即时差异化（0–6 月）**
- **品类唯一**：Lab OS 几乎无竞品——Paperguide 们服务"一个人"，飞书/Notion 不懂学科，学校科研管理系统是"填报型"不管过程
- 中文科研生态：知网/万方数据、国自然报销规则、保研套磁场景（国外产品进不来也不屑做）
- **证据可回溯**（借 Paperguide 的 Evidence Grid）：每句 AI 产出点回原文，验证成本 < 3 秒——机构验收唯一真正关心的东西
- 学术红线内建：教练不枪手、AIGC 披露、全程留痕

**中期壁垒（6–24 月）——三闭环 + 网络效应**
- 流程闭环：数据在系统内流转（复现记录→论文图表→投稿材料→结题报告），人肉搬运归零
- 角色闭环：四角色互相拉动，获客成本被网络摊薄
- 数据闭环：第 12 个月，换掉研擎 = 烧掉实验室的记忆
- 双向画像网络效应：学生证据越多 → PI 招生越准 → PI 越多 → 学生越愿意沉淀

**长期壁垒（24 月+）**
- **可复现性真值库**：从创始人自己的电力系统领域起步（MATPOWER/pandapower、OPF/状态估计/机组组合标准算例天然可评测）——每篇相关论文"能否复现、误差多少、需要什么环境"结构化沉淀，几千条后既是产品又是买不到的数据集
- 院级采购占坑：私有化 + 信创 + 等保三级 + 数据不出校，3–5 年合同，先发者极难被替换
- 连接器生态：每校一个 profile 的规则引擎，脏活累活即护城河

**竞争力公式**：单点 60 分 × 流程闭环 × 角色网络 × 数据复利 × 合规准入 = 结构性壁垒

## 七、信任设计（双端产品的生死线）

学生会不会在"导师能看见的系统"里真实记录？怕，就填假数据，驾驶舱变垃圾报表。三条铁律：
1. **可见性三级**（仅自己 / 对导师可见 / 组内公开）由学生控制，导师端不显示"是否有隐藏内容"
2. **数据边界合同**：哪些数据可用于画像与推荐、哪些永不离开学校，白纸黑字
3. **不与考核挂钩**：定位"帮扶与资源匹配"，一旦变成扣奖学金依据，数据立刻失真

## 八、落地节奏

**Beachhead**：创始人自己的主场——电气/电力系统方向的一个学院。理由：自己就是用户（需求不用猜）、算例可评测（真值库能起步）、期刊高度收敛（IEEE Trans. Power Systems 等，选刊能做得比通用工具准）、有 PI 关系能拿到首个付费 pilot。

**90 天验证（先验证付费，不先写代码）**
- Day 1–30：访谈 20 位 PI + 30 位研究生，问"上次组里项目卡住是因为什么"
- Day 31–60：Wizard-of-Oz 驾驶舱（后端人工、前端真实）给 2–3 个组免费用 6 周——**直接做 PI 驾驶舱，不做工具箱**
- Day 61–90：看 PI 周活、有没有组主动要求加入、有没有 PI 问价格；任一为否则回切"选刊 Recommender"单点

**北极星指标**：每周在平台上被完成的真实科研任务数
辅指标：PI 周活（≥2 次/周）、AI 产出证据回溯点击率、每组资产月增速

## 九、一页总结

> 别人在做科研工具（服务一个人的某一步），研擎在做**实验室的操作系统**（服务一个组的全流程）。
> 学生用它跑完第一篇论文，导师用它经营课题组，机构用它治理全院——
> 底下是同一群 AI 员工、同一份组内资产、同一套可审计的流程。
> **AI 从"侧边栏的回答者"变成"任务节点上的执行者与记录者"。**
